# schemas

- [Architecture schema][sokf:schema-architecture] - An architecture introduces a system to a reader new to it, in a hierarchy of diagrams: its context, its subsystems and their parts, its flows, where it runs, and its technology, with links to its contracts and designs.
- [Coding standard schema][sokf:schema-coding-standard] - A coding standard holds the project's rules for code in one language, grouped by topic, which a developer or an agent reads before writing or reviewing that code.
- [Contract schema][sokf:schema-contract] - A contract states what one building block promises its users, for any kind of interface, such as a command line or a file format: the interface, the acceptance criteria that it meets, its qualities and properties, and how it can change.
- [Design schema][sokf:schema-design] - A design explains how one building block is built, for the developer or agent who changes its code: its approach, its modules and how they work together, its interfaces and data, its limits, and the decisions behind it.
- [Documentation standard schema][sokf:schema-documentation-standard] - A documentation standard sets the rules for one kind of writing in the project, such as its prose, its formatting, or its schemas, grouped by topic.
- [Glossary schema][sokf:schema-glossary] - The canonical definitions of terms used throughout this project.
- [Grammar schema][sokf:schema-grammar] - The sidecar of a grammar file, the usage guide to the grammar it describes.
- [Issue schema][sokf:schema-issue] - An issue is a feature, a bug, a chore, or an epic, containing the work description, the plan for doing it, and (when completed) its outcome.
- [Non-goals schema][sokf:schema-non-goals] - A non-goals document lists what the project's system leaves out on purpose, each with its reason, for a developer or agent to check before adding a feature.
- [Project rules schema][sokf:schema-project-rules] - A project rules document holds the rules for every change to the repository, such as its commits, branches, and checks, grouped by topic. Rules for code and for writing belong in the standards.
- [Recipe schema][sokf:schema-recipe] - A recipe explains how to do one task on the project and when to do it, with one section for each step, in order.
- [Stories schema][sokf:schema-stories] - A Stories document holds the stories for one user goal, each saying what a kind of user needs and why, and each linking the contracts that deliver it.
- [tramlines-md specification schema][sokf:schema-tramlines-md-specification] - The one document that specifies the markdown format of tramlines, with its rules as EARS criteria keyed TLMD_n and its fixed texts in this schema.
- [tramlines specification schema][sokf:schema-tramlines-specification] - The one document that specifies tramlines, with its rules as EARS criteria keyed TL_n and its fixed texts in this schema.
- [Workflow schema][sokf:schema-workflow] - A workflow maps the order of work in a project, from an idea to a closed issue, in text diagrams: its stages, the path that each kind of work takes, the documents, and how the documents trace to the code.
